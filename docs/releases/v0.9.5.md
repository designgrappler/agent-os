# Release v0.9.5

## 1. Version

`v0.9.5`

## 2. Date

`2026-06-10`

## 3. Summary

This patch release delivers Sprint 16.5 — Hardening & Gap Closure. Five scoped protocol and skill edits close gaps identified during Sprint 13–16 planning: tracks.md template fields that were missing at Bridge time, a Bridge-enforcement loophole that let "small" requests bypass the protocol, a stale-reference gap in `refresh-agent-os`, compound-command script extraction for `streamline-approvals`, and a Research Phase §0 trigger correction in `architect.md` that removes the over-broad MANDATORY phrasing. No new skills are introduced and no runtime behavior is changed.

- **T16.5.1 — `onboard-existing-project` tracks.md template hardening:** Every track entry generated by `onboard-existing-project` now carries four required fields — `Plan reference`, typed `Files` buckets (`(new)`, `(edit)`, `(delete)`, `(read-only)`), `Migration Safety`, and `Security Review` — plus the standard DONE format `DONE — Bandit APPROVED, committed <hash> (<date>)`. Downstream sprints bootstrap with Bridge-ready track records.

- **T16.5.2 — Bridge enforcement hardening (CLAUDE.md + AGENTIC.md §5):** Both files now carry an explicit non-exemption clause in the Execution Protocol / Handoff Logic section. Phrases like "sounds small," "it's just one line," or "quick fix" are named as non-exemptions. The execution-files definition is explicit. Phrasing is identical across both files so future drift is detectable by diff.

- **T16.5.3 — `refresh-agent-os` Phase 7 CLAUDE.md Stale Reference Patch:** Adds Phase 7 to `refresh-agent-os`. When the diff from Phase 3 produced any changes, Phase 7 scans the project's `CLAUDE.md` against every `renames[].from` entry in the manifest and proposes per-hit rewrites to the corresponding `to` name. Absent `CLAUDE.md` is handled gracefully (prints one line, returns). Absent `docs/` or missing CLAUDE.md never errors.

- **T16.5.4 — `streamline-approvals` compound command script extraction:** When the same compound command (containing `&&`, `||`, `|`, `;`, `for`, `while`) appears 3 or more times across scanned transcripts, Step 9a proposes extracting it to `scripts/<name>.sh` and adding `Bash(bash scripts/<name>.sh)` to the allowlist. Compounds appearing fewer than 3 times continue to be reported as un-allowlistable. Scripts are written only on explicit user approval. Step 10's CANNOT ALLOWLIST bucket is updated to only list sub-threshold compounds; extracted scripts appear in a new EXTRACTED TO SCRIPTS bucket.

- **T16.5.5 — `architect.md` Research Phase §0 trigger correction:** The Research Phase heading and trigger block are rewritten. Old text: `MANDATORY before any plan or Bridge touching runtime behavior`. New text: `required ONLY when the plan contains a behavioral claim, or when the Conductor explicitly requests research` — with two explicit conditions enumerated. If neither trigger is present, the phase is skipped entirely. This eliminates unnecessary WebFetch calls on plans that contain no behavioral claims.

## 5. Compatibility Window

`frontmatter-version` remains `2`. No agent frontmatter fields were added, renamed, or removed.

The Research Phase §0 change in `architect.md` is a behavioral scope clarification — plans without behavioral claims no longer trigger WebFetch. Existing installs that have not run `/refresh-agent-os` will continue to use the old MANDATORY phrasing until they sync. The old behavior (always running §0) is safe; it is over-cautious, not incorrect.
