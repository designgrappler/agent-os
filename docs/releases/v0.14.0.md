# Release Notes — v0.14.0

**Date:** 2026-07-05
**Sprint:** S30 Track T30.B

## Summary

This release wires the Blueprint → Role Agent → Task Agent execution chain. A new generic `task-executor` subagent is registered as the runtime vehicle for all Task Agent spawns. The Skills Engineer (Skylar) agent definition is extended with the Blueprint spawn model: when a Bridge's Execution Files list spans two or more files, Skylar SHOULD decompose execution into Task Agent spawns by Reading the relevant blueprint and spawning `task-executor` with the blueprint body as the prompt. Every spawn produces one Task Agent Manifest entry in the Sign-Off. The QA agent definition is extended with a four-check Task Agent Manifest Gate that Bandit runs when any manifest entry is present. `AGENTIC.md` §11 codifies the full chain. `CLAUDE.md` carries a one-paragraph pointer to §11. Template sync (`claude/templates/AGENTIC.md`, `claude/templates/CLAUDE.md`) is deferred to the next canonical-sync sprint.

## Compatibility window

No new agent frontmatter fields were added. The `task-executor` agent is a new entry in `skills-manifest.json` `agents[]` — a backward-compatible additive change. No §9.2 compatibility window is triggered.

## User action required

Run `/refresh-agent-os` to install `task-executor` into `~/.claude/agents/task-executor.md` and receive the updated `skylar.md` and `bandit.md` (or project-equivalent QA agent).
