# Release v0.12.0

## 1. Version

`v0.12.0`

## 2. Date

`2026-06-27`

## 3. Summary

This release delivers two new behavioral capabilities and a prose-label sweep across all canonical protocol documents.

- **T26.A — MANUAL-mode hook enforcement:** `.claude/hooks/block-manual-agent-spawn.sh` now exits 2 (blocking) when the Sprint Coordinator main thread attempts an Agent or Task tool spawn while `operatingMode = "manual"`. Previously the hook exited 0 (informational). Subagent calls (`agent_id` present — Specialist, QA, or nested agent) and AUTONOMOUS mode are unaffected. The block is enforced before the permission prompt and cannot be overridden by approving the prompt. Note: `.claude/hooks/` is project-scoped — this change is NOT distributed to user installs via `/refresh-agent-os`. It is included in the release notes for completeness of the Sprint 26 narrative; `claude/templates/AGENTIC.md` §3 was also updated in T26.A to document the new exit-2 behavior.

- **T26.B — `streamline-approvals` profile execution:** Invoking `/streamline-approvals auto` or `/streamline-approvals manual` now applies the named profile — writing or removing the `Agent` and `Task` allowlist entries in `~/.claude/settings.json` — instead of running the transcript scanner. The no-argument path (`/streamline-approvals`) continues to invoke the transcript scanner as before. This closes Gap 6 from the Sprint 26 plan: the AUTONOMOUS mode switch requires a single `/streamline-approvals auto` invocation rather than manual settings edits.

- **T26.E — Prose-label sweep:** `AGENTIC.md`, `claude/templates/AGENTIC.md`, `CLAUDE.md`, and `claude/templates/CLAUDE.md` prose now describes MANUAL mode as "MANUAL mode (approval-gated)" and AUTONOMOUS mode as "AUTONOMOUS mode (auto-approve)". Internal `operatingMode` field values (`"manual"`, `"autonomous"`) are UNCHANGED — backward-compatible with all existing hook logic and settings checks. The project's `CLAUDE.md` Operating Mode section is also flipped from MANUAL to AUTONOMOUS to reflect the current project operating posture.

## 5. Compatibility Window

`frontmatter-version` remains `2`. No agent or skill frontmatter fields were added, renamed, or removed in this release.

Internal `operatingMode` values (`"manual"`, `"autonomous"`) are unchanged — old prose ("MANUAL mode") and new prose ("MANUAL mode (approval-gated)") are equally valid references to the same internal value; no migration required.

The hook exit-code change in T26.A affects only projects that have `.claude/hooks/block-manual-agent-spawn.sh` installed (project-scoped). Global installs are not affected.

Run `/refresh-agent-os` to pick up the updated `streamline-approvals` skill. Optionally run `/streamline-approvals auto` to enable hands-off Agent-spawn approval. No breaking changes.
