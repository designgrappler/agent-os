# Release v0.9.0

**Version:** v0.9.0
**Date:** 2026-05-24
**Sprint:** Sprint 9, Track T9.1

---

## Summary

This release introduces the canonical-update protocol for Agent OS — the first time agent files (not just skills) have a versioned, auditable refresh path. Before v0.9.0, `/refresh-agent-os` only diffed and updated skills; users who wanted updated agent profiles had to re-onboard or hand-edit. v0.9.0 closes that gap: the refresh tool now inventories canonical agents alongside skills, diffs them against your `~/.claude/agents/` install, surfaces release notes before offering writes, and applies changes on per-file confirmation. The manifest schema has been additively extended to carry the agent list, a frontmatter version counter, and the release version string. A formal compatibility window (minimum 2 sprints, binding) is now documented in AGENTIC.md §9 so future canonical changes — starting with T9.2's multi-provider frontmatter — propagate safely without breaking existing installs.

## Compatibility Window

No agent frontmatter fields were added in this release. The compatibility window machinery is being put in place here so that T9.2 (multi-provider `provider:` field) can use it safely.

**T9.2 compatibility window declared here:** when `provider:` is added in Sprint 9 T9.2, the window opens at Sprint 9 and closes no earlier than the end of Sprint 11. During that window, `provider:` absent defaults to `claude`. No user action is required during the window; running `/refresh-agent-os` will surface the drift and offer the upgrade with these notes.

---

## User Action Required

Run `/refresh-agent-os` to apply the updated `refresh-agent-os` skill and, if you have agents installed, to inventory and optionally update your `~/.claude/agents/` files against the canonical set.

No agent frontmatter changes ship in this release — no migration is required for existing agent installs.
