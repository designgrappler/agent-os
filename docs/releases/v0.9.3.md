# Release v0.9.3

## 1. Version

`v0.9.3`

## 2. Date

`2026-05-29`

## 3. Summary

This patch release closes five interconnected protocol and onboarding gaps surfaced after the Sprint 12 worktree-isolation post-mortem and the 2026-05-26 backlog review. The unifying theme: replace **textual protocol assertions** with **runtime-enforced or evidence-backed mechanisms**.

- **T13.1 — Worktree isolation + Architect Research Phase + QA Behavioral Verification:** Specialists now ship with `isolation: worktree` in frontmatter so the Claude Code runtime automatically provides CWD isolation — no manual worktree setup required. `.claude/settings.json` gains `worktree.baseRef: "head"` so Specialist worktrees branch from the current session HEAD (not `origin/HEAD`), carrying in-progress context. The Architect role gains a mandatory Research Phase §0 requiring every behavioural claim in a plan or Bridge to cite official Claude Code documentation; if WebFetch is unavailable, the Architect must surface this as a hard stop. The QA role gains a Behavioral Verification Gate (§4): Specialists must attach observed runtime output to Sign-Off, not paraphrased summaries. WebFetch is added to the `tools:` frontmatter of all agent definitions so every role can access primary documentation. The `install-agent-scaffold` skill §4f/§4g/§4h templates now emit all three additions (`isolation: worktree`, WebFetch in `tools:`, Behavioral Verification Sign-Off) in generated agent frontmatter so future scaffolded projects ship with the full shape.

- **T13.2 — Bridge Execution Files: typed buckets:** The Bridge `Execution Files` field is now three separate fields — `(source)`, `(tests)`, and `(tooling/config)` — so test files and tooling files are mandatory to enumerate at Bridge-write time. The Architect Bridge Self-Check Completeness gate requires all three buckets to be present (empty is fine with a one-line justification, but absent is not). The QA and Bandit Scope Gates read all three buckets as the authoritative allowlist.

- **T13.3 — Onboard hardening:** Two related fixes to `onboard-existing-project`. First, when CLAUDE.md is preserved unchanged, the skill now emits a structured auto-trigger table diff (inside the existing Sprint 5 T1 skill-reference drift sub-flow) and offers to patch only the auto-trigger table — no silent rewrite. Second, `product.md` creation is now skeleton-first: a skeleton file with a `<!-- TODO: fill in product context -->` placeholder is written before the user is prompted, guaranteeing the file always exists after onboarding even when the user defers. The Architect HARD STOP has been tightened to also treat the TODO marker as missing context (folded into T13.1's Architect role updates).

- **T13.4 — `/check-agent-os` legacy install detection:** Phase 4 of `/check-agent-os` now flags two additional gaps in existing onboarded installs: (a) agents missing `WebFetch` in their `tools:` frontmatter; (b) Specialists missing `isolation: worktree` in frontmatter. Both checks surface a FAIL line with the remediation hint "Run `/refresh-agent-os` to sync with canonical." The existing model-name short-format check is unchanged.

- **T13.5 — Release notes (this file):** documents all Sprint 13 user-facing changes per AGENTIC.md §9.1.

## 5. Compatibility Window

N/A — no frontmatter field changes in this release. `frontmatter-version` remains `2`.

The new `isolation: worktree` field in Specialist frontmatter is additive. Existing installed agents without this field continue to function; they simply do not receive automatic worktree isolation on Specialist invocation.

The new `WebFetch` entry in agent `tools:` frontmatter is additive. Agents without it continue to work; they will not be able to satisfy the Research Phase §0 WebFetch requirement until refreshed.

## 6. Migration Notes for Existing Installs

Two steps — detection first, then remediation:

1. **Detect gaps:** Run `/check-agent-os`. If your installed agents are missing `WebFetch` in `tools:` frontmatter or Specialists are missing `isolation: worktree`, the Phase 4 report surfaces FAIL lines with remediation hints.

2. **Apply updates:** Run `/refresh-agent-os` to diff your `~/.claude/agents/` against the v0.9.3 canonical templates and accept the changes. The diff covers `WebFetch` additions, `isolation: worktree` additions for Specialists, the Behavioral Verification Sign-Off field, and the research-flag Hard Constraint.

Projects onboarded with `install-agent-scaffold` before this release will need to add `worktree.baseRef: "head"` to their `.claude/settings.json` manually (one-line addition) to get the HEAD-branching behaviour for Specialist worktrees.

## 7. User Action Required

Run `/check-agent-os` to detect gaps, then `/refresh-agent-os` to apply the v0.9.3 canonical agent shape to your install.
