## 3. Summary

This release consolidates two sprint cycles of skill and protocol work into a single canonical drop. Sprint 15's T15.1 merges the historical `open-sprint` + `start-sprint` skills into a unified `/start-sprint` with two-mode routing and a temp interview doc as canonical sprint brief. Sprint 16's T16.1 and T16.2 codify the continuous improvement loop and add the binding §5.1 Canonical Sync Before Sprint Close protocol — every project-level improvement must now identify a canonical owner and queue a canonical-update track before sprint close, mirrored in the install template and gated through the Architect's Bridge Self-Check. No new agents are introduced and no agent frontmatter fields change.

- **T15.1 — Unified `/start-sprint` skill with two-mode routing + temp interview doc:** `open-sprint` and `start-sprint` are merged into a single `/start-sprint` skill with two execution modes. Mode A (Sprint Setup) runs the prior-sprint check, archives stale context, conducts the sprint interview, updates `docs/context/plan.md` and `docs/context/tracks.md`, and writes `docs/temp-sprint<N>-interview.md` as the canonical sprint brief that downstream planning reads from. Mode B (Parallel Kickoff) classifies open and blocked tracks and emits ready-to-paste tab prompts for parallel specialist invocation. The legacy `claude/skills/open-sprint/` directory is deleted. Cross-references in `onboard-existing-project/SKILL.md` are updated to point at the unified skill name.

- **T16.2 — AGENTIC.md §5.1 Canonical Sync Before Sprint Close:** A new §5.1 is added to `AGENTIC.md` as a binding Conductor protocol. Every improvement made during a sprint to a project-level artifact (`.claude/agents/*.md`, `.claude/settings.json`, the live `AGENTIC.md` or `CLAUDE.md`, project-level config) must have its canonical owner identified before the sprint closes, and a canonical-update track must be queued for the current or next sprint if canonical does not yet reflect the improvement. Sprint close is blocked while a canonical-sync-pending item has no queued track. The same section is mirrored into `claude/templates/AGENTIC.md` so fresh installs inherit the rule, and a cross-reference gate is added to `claude/agents/architect.md` Bridge Self-Check so Bridges that touch project-level artifacts surface the canonical-sync requirement.

- **T16.1 — Continuous improvement loop + canonical-sync backlog:** A loop summary paragraph is added to `AGENTIC.md` §5 alongside §5.1, codifying the standing protocol: fix locally → confirm it works → queue a targeted canonical-update backlog item naming the specific canonical file → process the item as a normal sprint track. Fifteen targeted canonical-sync backlog items are queued in `docs/context/tracks.md` to retire accumulated drift between project-level artifacts and their canonical owners. The same loop summary is mirrored into `claude/templates/AGENTIC.md`.
