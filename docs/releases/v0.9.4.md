# Release v0.9.4

## 1. Version

`v0.9.4`

## 2. Date

`2026-06-03`

## 3. Summary

This patch release delivers Sprint 14 — skill enhancements, a user feedback loop, an approvals framework, protocol hardening, and two correctness fixes. The unifying theme: **make the Agent OS skill library active maintenance infrastructure**, not just an install-time scaffold.

- **T14.1 A — `clean-context` migration:** Migrated `clean-context` from the Gemini-side `skills/` path to the canonical Claude path `claude/skills/clean-context/SKILL.md` with correct frontmatter. Added `clean-context` to `skills-manifest.json`. Gemini-side updated in parity.

- **T14.1 B — Memory hygiene scan in `clean-context`:** Adds a memory pruning step after the merged-branch sweep. Classifies memory files by prefix (`reference_*` / `feedback_*` / `project_*`), applies a two-signal 90-day staleness rule, and surfaces RETIRE candidates to the Conductor in a markdown report. Tombstone pattern: `STATUS: retired` written in-place — no deletions. Never auto-flags `reference_*` or `feedback_*` files.

- **T14.1 C — Memory compression target in `minify-context`:** Extends `minify-context` with an opt-in memory compression target. Applies the five-category R3 taxonomy: TRANSACTIONAL_STATE (4–6:1), FEEDBACK_RULES (2:1 max, verbatim phrasing preserved), REFERENCE_DOCS (1.1:1), PROTOCOL_CANON (1:1 — hard-excluded by path), NARRATIVE_CONTEXT (8:1). Writes `.minify-backup-<date>` before any rewrite. Never removes memory entries.

- **T14.1 D — `Created:` date convention:** Codifies the `Created: YYYY-MM-DD` memory authoring convention in `AGENTIC.md` and `claude/templates/AGENTIC.md`. Required for `project_*` files; optional for others. Forward-going only — no retroactive datestamping.

- **T14.1 E — SessionStart memory reminder:** Adds a second SessionStart hook to `.claude/settings.json` that prints one line if the newest memory file is older than 14 days: `Memory hygiene reminder — newest memory entry is N days old. Consider /clean-context or /minify-context.` Mirrored into `install-agent-scaffold` and `claude/templates/CLAUDE.md`.

- **T14.2 — `/submit-agent-os-feedback` + `/triage-feedback`:** Two new skills closing the user feedback loop. `/submit-agent-os-feedback` is a guided wizard that files structured GitHub Issues against `designgrappler/agent-os` with label `feedback`; hard-blocks on secret-shaped strings before submit. `/triage-feedback` reads open feedback issues, groups by theme, and surfaces triage candidates to the Conductor. `/start-sprint` now invokes `/triage-feedback` non-blocking in its information-gathering phase.

- **T14.3 — Approvals framework:** Implements the three-tier permission model in `.claude/settings.json` (Tier 1 fully-automated, Tier 2 human-confirmation, Tier 3 always-explicit). Key changes: replaces fragile `Bash(curl -s *)` with domain-scoped `WebFetch(domain:...)` allows; adds `ask` rules for protocol file edits (`AGENTIC.md`, agent files, skill files, `git commit/push`); adds `deny` rules for destructive/arbitrary-exec ops (`rm -rf`, force-push, `curl`, `wget`, `npx`, `bunx`, `eval`, `ssh`, `.env` paths). Authors `docs/streamline-approvals-v2-spec.md` covering Modes 2/3/4 for a future implementation sprint.

- **T14.4 — `refresh-agent-os` renames collision fix:** Adds a defensive cross-array invariant guard to Phase 3 of `refresh-agent-os`. When a skill name appears in both `renames[].from` and the canonical `skills` array (a §9.7.2 invariant violation), canonical `skills` membership is now authoritative — the skill is no longer incorrectly treated as removed. Surfaces a diagnostic warning when the invariant is violated.

- **T14.5 — EM no-planning rule codification:** Codifies the Orchestrator no-planning constraint in `AGENTIC.md` §3 and `CLAUDE.md` (this repo and canonical templates). The Orchestrator may never draft track specs, scope definitions, Red Flag Analyses, or Handoff Bridges. Fixes `start-sprint` Step 5 prompt template to emit `git worktree add` as the first instruction in every opening prompt — enforcing worktree isolation at the tab-kickoff layer, not just in protocol text.

## 5. Compatibility Window

`frontmatter-version` remains `2`. No breaking changes to agent frontmatter.

The new `permissions` block in `.claude/settings.json` is additive for new installs. Existing installs will see drift on next `/check-agent-os` — run `/refresh-agent-os` to sync settings and skill updates.

## 6. Migration Notes for Existing Installs

1. **Run `/refresh-agent-os`** to sync new and updated skills (`clean-context`, `minify-context`, `submit-agent-os-feedback`, `triage-feedback`, `start-sprint`, `refresh-agent-os`, `install-agent-scaffold`).
2. **Update `.claude/settings.json`** with the v0.9.4 three-tier permissions shape (see T14.3 changed files). The key changes: remove `Bash(curl -s *)`, add `WebFetch(domain:...)` allows, add `ask` rules for protocol files, add `deny` rules for destructive ops.
3. **Add the memory reminder hook** to your project's `.claude/settings.json` SessionStart array (see T14.1 E).

## 7. User Action Required

Run `/refresh-agent-os` to apply skill updates. Update `.claude/settings.json` permissions manually or re-run `/install-agent-scaffold` on a new project to get the v0.9.4 shape.
