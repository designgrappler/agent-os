# Release v0.10.0

## 1. Version

`v0.10.0`

## 2. Date

`2026-06-20`

## 3. Summary

This release delivers the task blueprint foundation for Agent OS — a new canonical content type that enables persona-agnostic task delegation via pre-authored blueprint files. Sprint 19 Tracks 19.1–19.4 collectively ship the schema, initial content, install-time scaffolding, and canonical-update protocol extension that form the complete distribution pipeline for blueprints alongside skills and agents.

- **T19.1 — Blueprint schema spec:** `claude/blueprints-schema.md` codifies the four-column blueprint schema (frontmatter: `name`, `description`, `tools`, `expected_output`, `model`, `schema_version`; body: System Prompt Strategy, Expected Output Contract, Allowed Tool Bindings — Reasoning). The schema encodes the five §8.3 stress-test conditions, the uniform `task-` prefix naming convention, the `expected_output:` frontmatter ↔ body first-sentence sync rule (machine-checkable), the two-strategy delegation framing, and a §11 Deferred decisions list. A cross-reference bullet is added to AGENTIC.md §1 DNA Taxonomy.

- **T19.2 — Initial blueprint set + manifest:** Three persona-agnostic task blueprints (`task-coder`, `task-writer`, `task-researcher`) are authored under `claude/blueprints/`, each conforming to the T19.1 schema with conservative tool allowlists. `blueprints-manifest.json` is introduced at the repo root as the canonical source of truth for blueprint names and rename history, mirroring the structural role of `skills-manifest.json`. No `release-version` field is present in `blueprints-manifest.json` — release-version lives in `skills-manifest.json` per §9.6.

- **T19.3 — Install-time blueprint scaffolding + health check:** `install-agent-scaffold/SKILL.md` is extended with a Claude-Code-only blueprint scaffolding step (Gemini installs skip it) that copies `claude/blueprints/<name>.md` to `~/.claude/blueprints/<name>.md` for every entry in `blueprints-manifest.json`. `check-agent-os/SKILL.md` is extended with Phase 7 (blueprint frontmatter validity check enforcing all six required fields, `name:`↔filename invariant, `task-` prefix, and the `expected_output:` first-sentence sync rule) and Phase 8 (passive Claude Code version notice using `claude --version` with defensive parsing; never affects OVERALL). Existing Phases 5 and 6 are renumbered to Phases 9 and 10.

- **T19.4 — Canonical-update protocol extension §9.8 + release v0.10.0:** AGENTIC.md §9.8 is added, codifying blueprints as the third canonical content type with §9.7.1 and §9.7.2 invariants extended to `blueprints-manifest.json`. The section is mirrored byte-identically to `claude/templates/AGENTIC.md` (canonical sync inline per §5.1), along with the Blueprint schema §1 cross-reference bullet. `refresh-agent-os/SKILL.md` is extended to inventory, diff, and apply blueprints as a third content type in Phase 2, Phase 3, Phase 4, Phase 5, Phase 6, and the Verification Checklist, with Phase 7 (CLAUDE.md stale reference scan) explicitly not extended. `skills-manifest.json` `release-version` is bumped to `v0.10.0`.

## 5. Compatibility Window

`frontmatter-version` remains `2`. No agent or skill frontmatter fields were added, renamed, or removed in this release.

The new blueprint content type carries its own per-file `schema_version: 1` field. Blueprint schema-version evolution is governed by AGENTIC.md §9.2's existing 2-sprint compatibility window — the same window that governs agent frontmatter evolution. The `schema_version: 1` field is the per-blueprint migration handle; missing-but-defaultable fields default to documented values per §9.2.

Users on prior installs are not retroactively migrated. `/refresh-agent-os` is the migration path — it now handles blueprints alongside skills and agents.

## 6. User Action Required

Run `/refresh-agent-os` to apply: (a) install the three canonical blueprints (`task-coder`, `task-writer`, `task-researcher`) into `~/.claude/blueprints/`; (b) pick up the updated `refresh-agent-os` skill carrying the third-content-type diff/install logic; (c) sync the updated `AGENTIC.md` template carrying §9.8 if your project's live `AGENTIC.md` should also receive §9.8 (existing project AGENTIC.md files are NOT auto-updated; project owners who want §9.8 in their live AGENTIC.md should copy the section manually). Run `/check-agent-os` after the refresh to confirm Phase 7 (blueprint frontmatter validity) passes against the freshly-installed set.
