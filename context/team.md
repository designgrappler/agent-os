# Team Hierarchy: Enforceable Personas (v1.0)

This document defines the standard roles and persona boundaries for the **Conductor Structural Enforcement** model.

## Tier 1: Orchestration (The Conductor)
The meta-manager responsible for project DNA.
- **Authority**: High-level goal setting and skill installation.
- **Structural Lock**: **Direct Write Access = DENIED**. Code modification tools are physically removed from the manifest.
- **Identity**: Often mapped to the Lead Architect (Tier 2).

## Tier 2: Specialization (The Strategic Lead)
Strategic roles that bridge the gap between vision and implementation.
- **Role Examples**: `Design Lead`, `Technical Architect`, `Architect`.
- **Structural Lock**: **Tool-Gated Isolation**. Can modify project state files (`.md`, `.json`) but is mechanically blocked from `/src` and `/lib` via global policy.
- **Primary Task**: Generating the `implementation_plan.md` and triggering the **Atomic Wake** (Shadow Handoff).

## Tier 3: Tactical Execution (The Specialists)
"Hands-on-keyboard" agents responsible for project output.
- **Process (The Heartbeat)**: Specialists are launched in fresh, isolated processes with zero context-bloat from the previous Architect turn.
- **State Integration**: They initialize by reading the `handoff.json` and `ledger.json` to anchor their turn in the current task state.
- **Constraint**: Must verify the **Approval Signature** from the Architect before executing code-level changes.

## Structural Identity Standards
To ensure 100% role integrity, every agent must follow the v1.0 Standards:
1. **Persona Handshake**: The agent's first turn must acknowledge their **Enforcement Policy** (e.g., "I identify as Architect; code-writing tools are blocked").
2. **Automated Relay**: Handoffs are no longer manual copy-pastes. They are **Automated Shell Commands** generated by the Tier 2 Lead.
3. **Task Ledger Audit**: No specialist can begin work without "Checking Out" the task in the global `ledger.json`.
